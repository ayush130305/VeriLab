A protocol is an agreement on four things: which wires exist, who drives them, when data is sampled, and where a transfer starts and ends.

UART

UART is an asynchronous, full-duplex, point-to-point link. Both sides agree on the baud rate, and the receiver re-aligns on every start bit.

  1. The line idles high. TX of one side goes to RX of the other, with a common ground.
  2. The start bit pulls the line low for one bit time. This edge is the timing reference.
  3. Data follows, usually 8 bits, least significant bit first.
  4. Optional parity: even makes the total count of ones even, odd makes it odd.
  5. One or two stop bits return the line high.

Play with it

On the FPGA

RX → 2-FF synchronizer → start detect → 16x tick → FSM → shift register → data, valid

  • On a low level, wait 8 ticks and check it is still low, to reject glitches. Then sample every 16 ticks.
  • FSM: IDLE, START, DATA, PARITY, STOP.
  • Divisor = clock / (baud × 16). At 100 MHz and 115200 it is 54.25. Using 54 gives +0.47% error.
  • Errors: framing (stop bit read as 0), parity, overrun (new byte before the old one was read), break (low longer than a frame).

Interview check

Answer aloud first, then open.

Why oversample by 16?

To find the start edge within 1/16 of a bit so samples land near the centre. It also allows majority voting.

Why a clock enable and not a divided clock?

A logic-made clock is a new clock domain on general routing. It adds skew, needs constraints and can glitch. An enable keeps one clock.

How much baud mismatch is allowed?

For 8N1 the ideal combined limit is about 5%. Design for about 2% per side.

Does parity correct errors?

No. It detects an odd number of flipped bits only.

SPI

SPI is a synchronous, full-duplex bus where one master clocks data to and from a selected slave. It is two shift registers in a ring.

SignalDriven byJob
SCLKMasterShift clock
MOSIMasterData to slave
MISOSelected slaveData to master
CS, active lowMasterSelects and frames the transfer

CPOL is the idle level of SCLK. CPHA = 0 samples on the first edge, CPHA = 1 on the second.

Play with it

On the FPGA

  • Master: SCLK from a counter and a register, a shift register, a bit counter. FSM: IDLE, ASSERT_CS, SHIFT, DEASSERT_CS.
  • Slave, simple way: synchronize SCLK and detect edges with the system clock. SCLK must be several times slower, commonly 4 times or more.
  • Slave, fast way: clock logic from SCLK and cross domains with a FIFO.
  • At high speed MISO has a round-trip delay, so the master may need to sample later.
  • Multiple slaves: one CS each with MISO released when unselected, or a daisy chain with one shared CS.

Interview check

Answer aloud first, then open.

SPI versus I2C?

SPI is faster and full duplex but needs a CS per slave and has no acknowledge. I2C uses two wires and addressing but is slower.

How does the master know the slave got the data?

It does not, unless a higher-level protocol reads back a status.

What if the modes differ?

Data is sampled while changing, giving shifted or corrupted bits.

QSPI

QSPI widens SPI to four bidirectional data lines, mainly for flash. Quad phases are half duplex.

Read phases: command, address, mode bits (optional), dummy clocks, data. The notation x-y-z is the number of lines for command, address, data.

Play with it

  • Dummy clocks give the flash time to fetch and the bus time to turn around. Counts vary by part, so read the datasheet.
  • Many parts need the Quad Enable bit set before IO2 and IO3 work.
  • Writing: Write Enable (0x06), program or erase, then poll the busy bit. Program only turns 1 into 0. Erase restores 1.
  • XIP: the CPU fetches instructions straight from flash through a memory-mapped controller.

Tri-state on the FPGA

// Bidirectional data pins to the flash
inout [3:0] io;
// Value to drive when the FPGA owns the bus
reg [3:0] io_out;
// Output enable, high when the FPGA drives
reg io_oe;
// Value seen on the pins
wire [3:0] io_in;

// Drive the pins only when enabled, otherwise release them
assign io = io_oe ? io_out : 4'bzzzz;
// Read back the pin values
assign io_in = io;

Interview check

Answer aloud first, then open.

Why are dummy cycles needed?

The flash needs time to access its array at high clock rates, and the lines must change direction.

Where do tri-states belong?

At the top level only. FPGAs have no internal tri-state buses.

I2C

I2C is a synchronous, half-duplex, two-wire bus with addresses and acknowledgement. Both wires are open-drain with pull-ups.

Open-drain means no two devices can short each other, and the bus is a wired AND: a 0 always wins.

EventDefinition
STARTSDA falls while SCL is high
STOPSDA rises while SCL is high
Data bitSDA changes while SCL is low, stable while high
ACKReceiver holds SDA low on the 9th clock
NACKSDA stays high on the 9th clock
Write:  S | addr | 0 | A | reg | A | data | A | P
Read:   S | addr | 0 | A | reg | A | Sr | addr | 1 | A | data | N | P

Play with it

Arbitration: two masters at once

Play with it

  • Clock stretching: a slave holds SCL low to pause. The master must read SCL back.
  • Sr (repeated START) changes direction without releasing the bus. The master NACKs the last read byte.
  • 10-bit addressing starts with 11110.
  • Pull-up minimum = (VDD − VOL) / IOL. Maximum = rise time / (0.8473 × bus capacitance).

On the FPGA

// Open-drain clock and data pins
inout scl, sda;
// High means pull the line low
reg scl_low, sda_low;

// Pull SCL low or release it to the pull-up
assign scl = scl_low ? 1'b0 : 1'bz;
// Pull SDA low or release it to the pull-up
assign sda = sda_low ? 1'b0 : 1'bz;

Split each bit into four phases using a clock enable. Synchronize both inputs. FSM: IDLE, START, ADDR, ACK, DATA, ACK, STOP.

Interview check

Answer aloud first, then open.

Why can I2C not run very fast?

The rising edge depends on a resistor charging the bus capacitance.

SDA is stuck low. What now?

A slave is mid-byte. Clock SCL up to 9 times until it releases SDA, then send STOP.

Does arbitration corrupt data?

No. The winner never notices. The loser stops driving.

I3C

I3C is the MIPI successor to I2C: the same two wires, much faster, with in-band interrupts and run-time address assignment.

Dynamic address assignment (ENTDAA)

Targets send their ID in open-drain. The lowest value wins, gets an address, and the round repeats. Press the button to run rounds. IDs here are shortened to 8 bits; real ones are 48 bits plus BCR and DCR.

Play with it

  • 0x7E is the broadcast address all I3C targets listen to.
  • CCCs (Common Command Codes) are standard bus management commands.
  • T-bit: odd parity on writes; on reads it says whether more data follows.
  • In-band interrupt: a target pulls SDA low on an idle bus, then sends its address.
  • Legacy I2C devices can share the bus if they do not stretch the clock.

Interview check

Answer aloud first, then open.

Why use open-drain only for part of the transfer?

Arbitration needs a wired AND. Push-pull is used elsewhere because it gives fast edges.

Who wins ENTDAA arbitration?

The numerically lowest ID, because 0 overrides a released line.

APB

APB is the simplest AMBA bus: no bursts, no pipelining, used for control and status registers.

Minimum cycles per transfer?

Two: one SETUP and one ACCESS.

Why is a bridge needed?

It translates fast bus transfers into APB phases and isolates slow peripherals.

AHB-Lite

AHB-Lite is a pipelined, single-master AMBA bus: the address of one transfer overlaps the data of the previous one.

SignalMeaning
HADDR, HWRITE, HSIZEAddress, direction, bytes per beat
HTRANSIDLE, BUSY, NONSEQ (first), SEQ (following)
HBURSTSINGLE, INCR, INCR4/8/16, WRAP4/8/16
HWDATA, HRDATAData
HREADYLow stretches the data phase and holds the next address
HRESPOKAY or ERROR

Play with it

  • A wrapping burst wraps at its size boundary, so a cache can fetch the missed word first.
  • An ERROR response takes two cycles so the next address can be cancelled.
  • Full AHB adds multiple masters and arbitration.

Interview check

Answer aloud first, then open.

APB versus AHB versus AXI?

APB for slow registers. AHB is pipelined with bursts on one shared path. AXI has independent channels and multiple outstanding transactions.

AXI4, Lite, Stream

AXI4 is a memory-mapped bus with five independent channels, each using the same valid/ready handshake.

ChannelDirectionCarries
AWMaster to slaveWrite address, burst info
WMaster to slaveData, strobes, WLAST
BSlave to masterOne response per write burst
ARMaster to slaveRead address, burst info
RSlave to masterData, response, RLAST

The handshake rules

  1. A transfer happens on a rising edge where VALID and READY are both 1.
  2. The source must not wait for READY before raising VALID. This prevents deadlock.
  3. Once VALID is high, it and the payload stay unchanged until the handshake.
  4. The destination may wait for VALID.
  5. BVALID comes only after the write address and last data are accepted.
  6. RVALID comes only after the read address is accepted.

Play with it

Bursts

Play with it

  • AxLEN = beats − 1. INCR allows up to 256 beats, others 16. WRAP uses 2, 4, 8 or 16.
  • AxSIZE: bytes per beat = 2 to the power AxSIZE.
  • No burst may cross a 4 KB boundary, so it cannot spill into another slave.
  • IDs allow outstanding requests. Different IDs may finish out of order. The same ID stays in order.
  • AXI4 has no WID and no write data interleaving.
  • Responses: OKAY, EXOKAY, SLVERR, DECERR. WSTRB has one bit per byte lane.

AXI4-Lite

The same five channels for registers: single beat only, no bursts, no IDs, 32 or 64 bit data.

// High for the cycle in which a write is accepted
wire wr_fire;
// Write response valid flag (declare as an output reg in the port list)
reg bvalid;

// Accept a write when address and data are present and no response is pending
assign wr_fire = awvalid && wvalid && !bvalid;
// Accept the address in the firing cycle
assign awready = wr_fire;
// Accept the data in the same cycle
assign wready = wr_fire;

// Holds the write response until the master accepts it
always @(posedge aclk) begin
    if (!aresetn)     bvalid <= 1'b0; // no response in reset
    else if (wr_fire) bvalid <= 1'b1; // write accepted, raise response
    else if (bready)  bvalid <= 1'b0; // response taken, clear it
end

AXI4-Stream

A one-way data pipe without addresses: TVALID, TREADY, TDATA, TLAST (end of packet), TKEEP and TSTRB (byte meaning), TUSER, TID, TDEST.

Backpressure: the receiver lowers TREADY and the pipeline holds. A skid buffer breaks long ready paths by storing the one extra word that arrives while ready is propagating.

Interview check

Answer aloud first, then open.

Can READY be high before VALID?

Yes, and it gives full throughput.

Can reads and writes happen together?

Yes, their channels are independent.

Why a write response channel?

The slave can confirm a write only after receiving its data.

CAN

CAN is a multi-master broadcast bus on a differential pair. There are no node addresses; the identifier sets the priority.

  • 0 is dominant, 1 is recessive. Dominant wins.
  • CANH and CANL with 120 ohm at each end. The FPGA needs a transceiver, connected by CAN_TX and CAN_RX.
  • Frame: SOF, ID (11 or 29 bits), RTR, control with DLC, data (0-8 bytes), CRC (15 bits), ACK, EOF.

Play with it

  • ACK: the sender releases the slot and any receiver with a good CRC drives it dominant.
  • Error states: active, passive (a counter above 127), bus-off (transmit counter above 255).
  • CAN FD carries up to 64 bytes with a faster data phase.
  • FPGA blocks: bit timing with time quanta and resync, stuff and destuff, CRC-15, arbitration compare, frame FSM.

Interview check

Why differential signalling?

Noise couples into both wires and cancels at the receiver.

Is arbitration destructive?

No. The winning frame continues unharmed.

I2S

I2S is a synchronous serial link for digital audio samples.

SignalMeaning
SCK (BCLK)Bit clock
WS (LRCLK)0 = left, 1 = right; frequency is the sample rate
SDData, MSB first

Play with it

  • In standard I2S the MSB appears one bit clock after WS changes. Data is sampled on the rising edge.
  • Many codecs also need MCLK, often 256 × sample rate.
  • FPGA: PLL for an accurate clock, counters for SCK and WS, shift registers, a FIFO to the processing clock.

Interview check

Answer aloud first, then open.

Formula for the bit clock?

Sample rate × bits per channel × 2.

MAC versus PHY?

MAC builds and checks frames digitally. PHY does line coding and analog signalling.

USB 2.0

USB is host-controlled: a device never speaks unless the host asks.

  • Speeds: low 1.5, full 12, high 480 Mbps.
  • D+ and D- differential. Pull-up on D+ means full speed, on D- low speed. High speed is negotiated after reset.
  • NRZI: a 0 toggles the line, a 1 holds it. After six 1s a 0 is stuffed.

Play with it

  • Packets: token (IN, OUT, SETUP, SOF), data, handshake (ACK, NAK, STALL).
  • Transfers: control (setup), bulk (reliable, no timing guarantee), interrupt (bounded latency), isochronous (guaranteed timing, no retry).
  • Enumeration: reset, read descriptors, assign address, select configuration.
  • FPGA: high speed normally needs an external ULPI PHY (8 bit, 60 MHz). Many designs use a USB-UART bridge.

Interview check

Answer aloud first, then open.

NAK versus STALL?

NAK: not ready, try again. STALL: cannot proceed without host action.

Why bit stuffing with NRZI?

A long run of 1s causes no transitions, so the receiver would lose timing.

Answer aloud first, then open.

Why not 2-FF each bit of a bus?

Bits can land in different cycles and form a value that never existed. Use a handshake or async FIFO.

Why Gray code in FIFO pointers?

One bit changes per step, so a sample is either the old or new value.

What is metastability?

A flip-flop with violated setup or hold takes an unpredictable time to settle.

How do you verify a protocol block?

Simulate against a model of the other side, include errors and back-to-back transfers, assert handshake rules, then check on hardware with a logic analyzer.
