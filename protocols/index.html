Start here

A protocol is an agreement on four things: which wires exist, who drives them, when data is sampled, and where a transfer starts and ends.

TermMeaning
SynchronousA clock travels with the data.
AsynchronousNo clock is sent. The receiver recovers timing from the data.
Simplex, half, full duplexOne way only; both ways one at a time; both ways at once.
Master or controllerStarts the transfer.
Slave or targetResponds.
Push-pullActively drives both 0 and 1.
Open-drainOnly pulls low. A resistor pulls high.
SDR, DDRData on one clock edge; on both edges.

Theory in depth

Serial versus parallel

A parallel link moves many bits per clock but needs every wire to arrive together. As clocks rise, the difference in arrival time between wires (skew) eats the timing budget, along with crosstalk and pin count. Serial links send one bit stream per lane and run it very fast. That is why off-chip links are mostly serial while on-chip buses stay parallel, where wires are short and timing is analysed by the tools.

Layers: wire, frame, transaction
  • Physical: voltage levels, push-pull or open-drain, single-ended or differential, termination.
  • Link or framing: where a unit starts and ends, addressing, error check, acknowledge.
  • Transaction: what the exchange means, such as "read register 0x10".

In an interview, describe any protocol in this order. It stops you from jumping around.

Electrical signalling

Single-ended signals are measured against ground, so ground noise and coupling add straight onto them. Differential signals use two wires with opposite polarity and the receiver looks only at the difference, so noise common to both cancels. Termination matters when the wire is long compared with the signal edge: an unmatched end reflects energy back and distorts later bits.

Raw rate versus useful throughput

Useful throughput = raw bit rate × payload bits ÷ total bits on the wire. UART 8N1 sends 10 bits for 8 of data, so 115200 baud carries at most 11520 bytes per second. Always count start, stop, address, acknowledge, CRC and gaps.

UART

UART is an asynchronous, full-duplex, point-to-point link. Both sides agree on the baud rate, and the receiver re-aligns on every start bit.

  1. The line idles high. TX of one side goes to RX of the other, with a common ground.
  2. The start bit pulls the line low for one bit time. This edge is the timing reference.
  3. Data follows, usually 8 bits, least significant bit first.
  4. Optional parity: even makes the total count of ones even, odd makes it odd.
  5. One or two stop bits return the line high.

Theory in depth

Why it needs a start bit

No clock is sent, so the receiver has no idea where a bit begins. The line idles high, and the falling edge of the start bit is the only timing reference. The receiver counts from that edge: 1.5 bit times later is the middle of the first data bit. The stop bit guarantees the line is high again, so the next start bit produces a fresh edge.

Timing error budget

The last sample of an 8N1 frame (the stop bit) is 9.5 bit times after the start edge. It must still land inside the correct bit, so the accumulated drift must stay under half a bit: 0.5 ÷ 9.5 ≈ 5.3% total. With 16x oversampling the start edge itself is uncertain by up to 1/16 bit, leaving about 4.6%. This is shared between transmitter and receiver, and slow edges reduce it further.

Frame notation and efficiency

"8N1" means 8 data bits, no parity, 1 stop bit.

FormatBits on wireData efficiency
8N11080%
8E11173%
8N21173%
Flow control
  • Hardware (RTS/CTS): extra wires. The receiver signals when it can accept data.
  • Software (XON/XOFF): special bytes 0x11 and 0x13 in the data stream. No extra wires, but awkward for binary data.
  • Without either, the receiver needs a FIFO large enough for the longest time it is busy.
UART is not RS-232

UART describes the framing. The voltage standard is separate.

StandardLevelsUse
TTL or CMOS UART0 V and 3.3 or 5 VChip to chip, FPGA pins
RS-232About ±3 to ±15 V, logic 1 is negativePC serial ports, needs a level shifter
RS-485Differential, multi-dropLong industrial links

Never wire RS-232 straight to an FPGA pin.

Majority voting and break

Instead of one centre sample, take three (for example ticks 7, 8, 9) and use the majority, which removes a single noise spike. A break holds the line low for longer than a whole frame and is used as an out-of-band signal such as "reset" or "attention".

Play with it

On the FPGA

RX → 2-FF synchronizer → start detect → 16x tick → FSM → shift register → data, valid

  • On a low level, wait 8 ticks and check it is still low, to reject glitches. Then sample every 16 ticks.
  • FSM: IDLE, START, DATA, PARITY, STOP.
  • Divisor = clock / (baud × 16). At 100 MHz and 115200 it is 54.25. Using 54 gives +0.47% error.
  • Errors: framing (stop bit read as 0), parity, overrun (new byte before the old one was read), break (low longer than a frame).

Interview check

Answer aloud first, then open.

Why oversample by 16?

To find the start edge within 1/16 of a bit so samples land near the centre. It also allows majority voting.

Why a clock enable and not a divided clock?

A logic-made clock is a new clock domain on general routing. It adds skew, needs constraints and can glitch. An enable keeps one clock.

How much baud mismatch is allowed?

For 8N1 the ideal combined limit is about 5%. Design for about 2% per side.

Does parity correct errors?

No. It detects an odd number of flipped bits only.

SPI

SPI is a synchronous, full-duplex bus where one master clocks data to and from a selected slave. It is two shift registers in a ring.

SignalDriven byJob
SCLKMasterShift clock
MOSIMasterData to slave
MISOSelected slaveData to master
CS, active lowMasterSelects and frames the transfer

CPOL is the idle level of SCLK. CPHA = 0 samples on the first edge, CPHA = 1 on the second.

Theory in depth

The ring of shift registers

Master and slave each hold a shift register, connected head to tail through MOSI and MISO. Every clock moves one bit each way, so after 8 clocks the two bytes have swapped. A "read" is therefore a write of dummy bytes, and a "write" receives bytes you ignore.

Launch edge and sample edge

One edge changes data and the opposite edge samples it, giving half a period for the signal to travel and settle.

ModeCPOLCPHASamples on
000Rising
101Falling
210Falling
311Rising

With CPHA = 0 there is no clock edge before the first sample, so the first bit must already be on the line when CS falls. Modes 0 and 3 are the most common.

What limits the clock speed

On a read, the clock travels to the slave and the data travels back within the same half period:

T/2 ≥ clock delay to slave + slave clock-to-output + data delay back + master setup

This is why reads usually fail before writes. Fixes: sample on a later edge, use an I/O register, or use a feedback clock.

No standard

SPI came from Motorola and has no single formal specification. Word length, bit order, CS behaviour between bytes and command format all come from the device datasheet.

Variants
  • Three-wire SPI: one shared data line, half duplex.
  • Daisy chain: slaves form one long shift register under one CS. Pins are saved, but latency grows with chain length.
  • Dual and quad: more data lines, see QSPI.
What SPI does not give you

No addressing, no acknowledge, no flow control, no error check. If you need any of them, you add them in the command layer, for example a status register or a CRC byte.

Play with it

On the FPGA

  • Master: SCLK from a counter and a register, a shift register, a bit counter. FSM: IDLE, ASSERT_CS, SHIFT, DEASSERT_CS.
  • Slave, simple way: synchronize SCLK and detect edges with the system clock. SCLK must be several times slower, commonly 4 times or more.
  • Slave, fast way: clock logic from SCLK and cross domains with a FIFO.
  • At high speed MISO has a round-trip delay, so the master may need to sample later.
  • Multiple slaves: one CS each with MISO released when unselected, or a daisy chain with one shared CS.

Interview check

Answer aloud first, then open.

SPI versus I2C?

SPI is faster and full duplex but needs a CS per slave and has no acknowledge. I2C uses two wires and addressing but is slower.

How does the master know the slave got the data?

It does not, unless a higher-level protocol reads back a status.

What if the modes differ?

Data is sampled while changing, giving shifted or corrupted bits.

QSPI

QSPI widens SPI to four bidirectional data lines, mainly for flash. Quad phases are half duplex.

Read phases: command, address, mode bits (optional), dummy clocks, data. The notation x-y-z is the number of lines for command, address, data.

Theory in depth

How a NOR flash is organised
UnitTypical sizeOperation
Page256 bytesProgram (write)
Sector4 KBSmallest erase
Block32 or 64 KBFaster bulk erase
ChipAllFull erase

A page program that runs past the end of the page wraps to the start of the same page and corrupts it.

Common commands
OpcodeJob
0x9FRead JEDEC ID, a good first bring-up test
0x06Write Enable
0x05Read status register 1 (bit 0 busy, bit 1 write-enable latch)
0x02Page program
0x204 KB sector erase
0xD864 KB block erase

These are widely shared, but confirm them in your flash datasheet.

The write sequence
  1. Send Write Enable (0x06), then raise CS.
  2. Send the program or erase command with its address.
  3. Raise CS. The internal operation starts only now.
  4. Poll the status register until busy = 0.

Program takes up to milliseconds and erase far longer, so a controller must never assume it is done.

Mode bits, dummy clocks and continuous read

Mode bits follow the address on I/O reads. A special value tells the flash that the next transaction will skip the opcode and start with the address (continuous read), which cuts latency for XIP. Always know how to exit it: a flash left in that mode will misread the next command after an FPGA reset.

Throughput

A 1-4-4 read of 32 bytes costs 8 clocks of command, 6 of address, 6 of mode and dummy (part dependent) and 64 of data: 84 clocks, so 76% efficient. Short random reads are far worse, which is why XIP systems add a cache or prefetch buffer.

Addressing beyond 16 MB

Three address bytes reach 16 MB. Larger parts use 4-byte address commands or a 4-byte mode. Related faster modes are DTR (data on both edges) and octal SPI (8 lines).

Play with it

  • Dummy clocks give the flash time to fetch and the bus time to turn around. Counts vary by part, so read the datasheet.
  • Many parts need the Quad Enable bit set before IO2 and IO3 work.
  • Writing: Write Enable (0x06), program or erase, then poll the busy bit. Program only turns 1 into 0. Erase restores 1.
  • XIP: the CPU fetches instructions straight from flash through a memory-mapped controller.

Tri-state on the FPGA

// Bidirectional data pins to the flash

// Value to drive when the FPGA owns the bus

// Output enable, high when the FPGA drives

// Value seen on the pins

// Drive the pins only when enabled, otherwise release them
assign io = io_oe ? io_out : 4'bzzzz;

Answer aloud first, then open.

Why are dummy cycles needed?

The flash needs time to access its array at high clock rates, and the lines must change direction.

Where do tri-states belong?

At the top level only. FPGAs have no internal tri-state buses.

I2C

I2C is a synchronous, half-duplex, two-wire bus with addresses and acknowledgement. Both wires are open-drain with pull-ups.

Open-drain means no two devices can short each other, and the bus is a wired AND: a 0 always wins.

EventDefinition
STARTSDA falls while SCL is high
STOPSDA rises while SCL is high
Data bitSDA changes while SCL is low, stable while high
ACKReceiver holds SDA low on the 9th clock
NACKSDA stays high on the 9th clock
Write:  S | addr | 0 | A | reg | A | data | A | P
Read:   S | addr | 0 | A | reg | A | Sr | addr | 1 | A | data | N | P

Theory in depth

Why open-drain

Several masters and slaves share two wires. If one drove high while another drove low, current would fight through both. With open-drain a device only pulls low or lets go, so the worst case is a harmless 0. That one property gives arbitration, clock stretching and acknowledge for free.

Speed modes
ModeMax rateMax rise time
Standard100 kbit/s1000 ns
Fast400 kbit/s300 ns
Fast-mode Plus1 Mbit/s120 ns
High-speed3.4 Mbit/sSpecial rules
Ultra Fast5 Mbit/s, write only, push-pullSeparate bus

Standard and Fast mode limit bus capacitance to 400 pF.

Pull-up trade-off

A small resistor gives a fast rise but more current when pulled low, and the driver may fail to reach a valid low. A large resistor saves power but the rise is slow. Example at 3.3 V, 3 mA sink, VOL 0.4 V: minimum ≈ 967 Ω. With 100 pF at 400 kHz: maximum ≈ 3.5 kΩ.

Clock synchronization between masters

SCL is also a wired AND. The low period lasts as long as the slowest device holds it low, and the high period ends when the first master pulls it down. Both masters therefore see one common clock and can arbitrate bit by bit on SDA.

Addresses
  • 7 bits give 128 values, but 0000xxx and 1111xxx are reserved, leaving 112.
  • 0x00 is the General Call to all devices.
  • The byte on the wire is address × 2 + R/W. Datasheets sometimes quote the 8-bit form, a classic bring-up bug.
Register read, step by step

A slave has an internal register pointer. You first write the register number, then issue a repeated START and read. The repeated START keeps another master from slipping in and moving the pointer. The master ACKs a byte if it wants another one, and NACKs the last one so the slave releases SDA.

SMBus

SMBus is a stricter relative used on PC boards. It adds a minimum clock rate and a timeout, so a hung device cannot hold the bus forever.

Play with it

Arbitration: two masters at once

Play with it

  • Clock stretching: a slave holds SCL low to pause. The master must read SCL back.
  • Sr (repeated START) changes direction without releasing the bus. The master NACKs the last read byte.
  • 10-bit addressing starts with 11110.
  • Pull-up minimum = (VDD − VOL) / IOL. Maximum = rise time / (0.8473 × bus capacitance).

On the FPGA

// Open-drain clock and data pins
inout scl, sda;
// High means pull the line low
reg scl_low, sda_low;

// Pull SCL low or release it to the pull-up
assign scl = scl_low ? 1'b0 : 1'bz;
// Pull SDA low or release it to the pull-up
assign sda = sda_low ? 1'b0 : 1'bz;

Split each bit into four phases using a clock enable. Synchronize both inputs. FSM: IDLE, START, ADDR, ACK, DATA, ACK, STOP.

Interview check

Answer aloud first, then open.

Why can I2C not run very fast?

The rising edge depends on a resistor charging the bus capacitance.

SDA is stuck low. What now?

A slave is mid-byte. Clock SCL up to 9 times until it releases SDA, then send STOP.

Does arbitration corrupt data?

No. The winner never notices. The loser stops driving.

I3C

I3C is the MIPI successor to I2C: the same two wires, much faster, with in-band interrupts and run-time address assignment.

FeatureI2CI3C Basic
DriveOpen-drainOpen-drain for arbitration, push-pull for data
SCLUp to 3.4 MHzUp to 12.5 MHz SDR
AddressFixedDynamic
InterruptExtra wireIn-band on SDA
9th bitACK/NACKACK for address, T-bit for data
Clock stretchingAllowedNot by targets
Hot-joinNoYes

Theory in depth

Why it was created

Sensor-heavy products ran into I2C limits: slow edges from pull-ups, power wasted in those resistors, fixed addresses that collide, and a separate interrupt wire per sensor. I3C fixes these while keeping two wires.

Roles and drive modes
  • The controller always drives SCL, in push-pull. Targets cannot stretch it.
  • SDA is open-drain where several devices may talk at once (address arbitration, ACK, DAA).
  • SDA is push-pull for data, giving fast edges.
  • The controller manages the SDA pull-up and keeper itself.
Provisional ID, BCR, DCR
FieldSizeTells the controller
PID48 bitsMaker and part identity
BCR8 bitsBus capabilities, such as IBI behaviour
DCR8 bitsDevice type

During ENTDAA these 64 bits arbitrate, so every unaddressed target gets a 7-bit dynamic address in turn.

Ways to give an address
  • ENTDAA: arbitration based, no prior knowledge needed.
  • SETDASA: assign to a target using its known static address.
  • SETAASA: tell targets to use their static addresses as dynamic ones.
  • RSTDAA clears assignments.
CCC codes worth knowing
CodeName
0x00 / 0x80ENEC, enable events (broadcast / direct)

Broadcast CCCs are 0x00 to 0x7F. Direct CCCs, which name a target, start at 0x80.

In-band interrupt and hot-join

On an idle bus a target pulls SDA low. The controller starts clocking and the target sends its own address; if several ask, the lowest address wins. The controller ACKs or NACKs, and a data byte may follow if the target declares it. A hot-joining device sends the reserved address 0x02, after which the controller runs address assignment for it.

Mixed bus and HDR

Legacy I2C targets with a 50 ns spike filter do not see the very short SCL high pulses used in I3C push-pull traffic, so they can stay on the bus. HDR modes (such as HDR-DDR) raise the data rate and are entered with a CCC.

Dynamic address assignment (ENTDAA)

Targets send their ID in open-drain. The lowest value wins, gets an address, and the round repeats. Press the button to run rounds. IDs here are shortened to 8 bits; real ones are 48 bits plus BCR and DCR.

Play with it

  • 0x7E is the broadcast address all I3C targets listen to.
  • CCCs (Common Command Codes) are standard bus management commands.
  • T-bit: odd parity on writes; on reads it says whether more data follows.
  • In-band interrupt: a target pulls SDA low on an idle bus, then sends its address.
  • Legacy I2C devices can share the bus if they do not stretch the clock.

Interview check

Answer aloud first, then open.

Why use open-drain only for part of the transfer?

Arbitration needs a wired AND. Push-pull is used elsewhere because it gives fast edges.

Who wins ENTDAA arbitration?

The numerically lowest ID, because 0 overrides a released line.

APB

APB is the simplest AMBA bus: no bursts, no pipelining, used for control and status registers.

SignalMeaning
PCLK, PRESETnClock, active-low reset
PADDR, PWRITEAddress, direction
PSELPeripheral selected
PENABLEAccess phase
PWDATA, PRDATAWrite, read data
PREADYLow adds wait states
PSLVERRError
  1. IDLE: PSEL = 0.
  2. SETUP: PSEL = 1, PENABLE = 0, exactly one cycle.
  3. ACCESS: PSEL = 1, PENABLE = 1, held while PREADY = 0.

Theory in depth

Where it sits

A processor reaches fast memory over AXI or AHB. A bridge turns accesses in the peripheral address range into APB transfers. APB peripherals (UART, GPIO, timers) stay tiny because they need no pipeline logic.

Versions
VersionAdds
APB2Basic SETUP and ACCESS
APB3PREADY, PSLVERR
APB4PSTRB byte strobes, PPROT protection
Stability rules
  • PADDR, PWRITE, PSEL and PWDATA stay unchanged from SETUP until the transfer completes.
  • The transfer completes on the edge where PSEL, PENABLE and PREADY are all 1.
  • PRDATA and PSLVERR are valid in that final cycle.
Writing a slave
wr_en = PSEL & PENABLE & PREADY &  PWRITE
rd_en = PSEL & PENABLE & PREADY & ~PWRITE

Include PENABLE, otherwise a write happens twice. This matters for registers with side effects such as a FIFO push or write-1-to-clear.

Address decoding

One decoder drives a separate PSELx per slave. A multiplexer returns PRDATA, PREADY and PSLVERR from the selected one.

AHB-Lite

AHB-Lite is a pipelined, single-master AMBA bus: the address of one transfer overlaps the data of the previous one.

SignalMeaning
HADDR, HWRITE, HSIZEAddress, direction, bytes per beat
HTRANSIDLE, BUSY, NONSEQ (first), SEQ (following)
HBURSTSINGLE, INCR, INCR4/8/16, WRAP4/8/16
HWDATA, HRDATAData
HREADYLow stretches the data phase and holds the next address
HRESPOKAY or ERROR

Theory in depth

The pipeline idea

Each transfer has an address phase (one cycle when the bus is ready) and a data phase that follows. While data for A is moving, the address for B is already out. With no wait states that gives one transfer per cycle.

HTRANS encoding
ValueNameMeaning
00IDLENo transfer
01BUSYMaster pauses inside a burst
10NONSEQFirst beat or single
11SEQFollowing beat of a burst
HREADY and HREADYOUT

Each slave outputs HREADYOUT. A multiplexer selects the one for the slave in the data phase and broadcasts it as HREADY to everyone. A slave accepts a new address only when HSEL is set, HREADY is high and HTRANS is NONSEQ or SEQ.

The classic slave bug

Address and control arrive one cycle before write data. A slave must register them in the address phase and use the registered copy when HWDATA arrives. With block RAM, a write followed immediately by a read can conflict on the port, so controllers add a wait state or forward the data.

Burst and alignment rules
  • Addresses are aligned to the transfer size.
  • A burst must not cross a 1 KB boundary.
  • HSIZE and HBURST stay constant during the burst.
Two-cycle error

Cycle 1: HRESP = ERROR, HREADY = 0. Cycle 2: HRESP = ERROR, HREADY = 1. The extra cycle lets the master withdraw the address already in the pipeline.

Play with it

  • A wrapping burst wraps at its size boundary, so a cache can fetch the missed word first.
  • An ERROR response takes two cycles so the next address can be cancelled.
  • Full AHB adds multiple masters and arbitration.

Interview check

Answer aloud first, then open.

APB versus AHB versus AXI?

APB for slow registers. AHB is pipelined with bursts on one shared path. AXI has independent channels and multiple outstanding transactions.

AXI4, Lite, Stream

AXI4 is a memory-mapped bus with five independent channels, each using the same valid/ready handshake.

ChannelDirectionCarries
AWMaster to slaveWrite address, burst info
WMaster to slaveData, strobes, WLAST
BSlave to masterOne response per write burst
ARMaster to slaveRead address, burst info
RSlave to masterData, response, RLAST

Theory in depth

Why five channels

Splitting address, data and response lets each direction flow at its own pace. A master can queue several read addresses before the first data returns (outstanding transactions), hiding the latency of slow memory. Because channels are one-way handshakes, you can insert a register on any of them to meet timing.

Dependencies
  • No VALID may depend combinationally on the matching READY.
  • B waits for both the AW handshake and the last W handshake.
  • R waits for the AR handshake.
  • AXI4 does not require AW before W. A slave must cope with either order.
Encodings
FieldValues
AxBURST00 FIXED, 01 INCR, 10 WRAP
xRESP00 OKAY, 01 EXOKAY, 10 SLVERR, 11 DECERR
AxSIZE0 = 1 byte, 1 = 2, 2 = 4, 3 = 8 ...

SLVERR: the slave was reached but failed. DECERR: no slave exists at that address.

Strobes and unaligned access

WSTRB marks which byte lanes of WDATA are valid. For an unaligned start address, the first beat enables only the upper lanes, and later beats are aligned.

Other sideband signals
SignalPurpose
AxCACHEBufferable and cacheable hints

Register slices and reset

A direct register on VALID and data breaks the forward path but not READY. A skid buffer registers both directions without losing throughput. During reset every VALID must be low; ARESETn may assert asynchronously but deasserts synchronously to ACLK.

Bandwidth

Peak = data width in bytes × clock. A 64-bit bus at 200 MHz gives 1.6 GB/s per direction. You approach it only with long bursts and enough outstanding requests to cover the memory latency.

The handshake rules

  1. A transfer happens on a rising edge where VALID and READY are both 1.
  2. The source must not wait for READY before raising VALID. This prevents deadlock.
  3. Once VALID is high, it and the payload stay unchanged until the handshake.
  4. The destination may wait for VALID.
  5. BVALID comes only after the write address and last data are accepted.
  6. RVALID comes only after the read address is accepted.

Play with it

Bursts

Play with it

  • AxLEN = beats − 1. INCR allows up to 256 beats, others 16. WRAP uses 2, 4, 8 or 16.
  • AxSIZE: bytes per beat = 2 to the power AxSIZE.
  • No burst may cross a 4 KB boundary, so it cannot spill into another slave.
  • IDs allow outstanding requests. Different IDs may finish out of order. The same ID stays in order.
  • AXI4 has no WID and no write data interleaving.
  • Responses: OKAY, EXOKAY, SLVERR, DECERR. WSTRB has one bit per byte lane.

AXI4-Lite

The same five channels for registers: single beat only, no bursts, no IDs, 32 or 64 bit data.

// High for the cycle in which a write is accepted
wire wr_fire;
// Write response valid flag (declare as an output reg in the port list)
reg bvalid;

// Accept a write when address and data are present and no response is pending
assign wr_fire = awvalid && wvalid && !bvalid;
// Accept the address in the firing cycle
assign awready = wr_fire;
// Accept the data in the same cycle
assign wready = wr_fire;

// Holds the write response until the master accepts it
always @(posedge aclk) begin
    if (!aresetn)     bvalid <= 1'b0; // no response in reset
    else if (wr_fire) bvalid <= 1'b1; // write accepted, raise response
    else if (bready)  bvalid <= 1'b0; // response taken, clear it
end

AXI4-Stream

A one-way data pipe without addresses: TVALID, TREADY, TDATA, TLAST (end of packet), TKEEP and TSTRB (byte meaning), TUSER, TID, TDEST.

Backpressure: the receiver lowers TREADY and the pipeline holds. A skid buffer breaks long ready paths by storing the one extra word that arrives while ready is propagating.

Answer aloud first, then open.

Can READY be high before VALID?

Yes, and it gives full throughput.

Can reads and writes happen together?

Yes, their channels are independent.

The slave can confirm a write only after receiving its data.

CAN

CAN is a multi-master broadcast bus on a differential pair. There are no node addresses; the identifier sets the priority.

  • 0 is dominant, 1 is recessive. Dominant wins.
  • CANH and CANL with 120 ohm at each end. The FPGA needs a transceiver, connected by CAN_TX and CAN_RX.
  • Frame: SOF, ID (11 or 29 bits), RTR, control with DLC, data (0-8 bytes), CRC (15 bits), ACK, EOF.

Theory in depth

Why it exists

Bosch designed it for cars, replacing bundles of point-to-point wires with one shared pair. Messages are labelled by content, not destination: every node hears every frame and filters by identifier. Adding a listener changes nothing for the senders.

Five error checks
  • Bit: the sender reads back a different level (outside arbitration and ACK).
  • Stuff: six equal bits where stuffing applies.
  • CRC: computed value differs.
  • Form: a fixed-format bit is wrong.
  • ACK: nobody acknowledged.
Fault confinement

Each node keeps a transmit counter (TEC) and a receive counter (REC). Errors raise them (a transmit error typically adds 8), successes lower them by 1.

StateConditionBehaviour
Error activeBoth ≤ 127Sends 6 dominant bits as an error flag
Error passiveEither > 127Sends 6 recessive bits, cannot disturb others
Bus offTEC > 255Stops. Rejoins after 128 runs of 11 recessive bits
Bit timing

One bit is split into time quanta: SYNC, PROP, PHASE1, PHASE2. The sample point is at the end of PHASE1, often 75 to 87.5% into the bit. Receivers hard-sync on SOF and then stretch or shorten phases by up to SJW to track edges.

Speed versus length

Arbitration needs a bit to reach the far node and the reply to come back before the sample point. So longer buses must run slower: roughly 40 m at 1 Mbps.

CAN FD

The arbitration phase stays at the classic rate. A bit-rate switch then speeds up the data phase, where only one node is talking. Payload reaches 64 bytes with a longer CRC (17 or 21 bits), and there are no remote frames.

I2S

I2S is a synchronous serial link for digital audio samples.

SignalMeaning
SCK (BCLK)Bit clock
WS (LRCLK)0 = left, 1 = right; frequency is the sample rate
SDData, MSB first

Theory in depth

Audio basics you need

Sound is sampled at a fixed rate and each sample is a signed two's complement number. Sampling at 48 kHz captures frequencies up to 24 kHz (Nyquist). Each extra bit of resolution adds about 6 dB of dynamic range.

Why MSB first and a one-bit delay

Sending the MSB first lets two devices with different word lengths work together: a shorter receiver ignores the extra low bits, and a longer one fills zeros. The one-clock delay after WS changes gives the receiver time to notice the new channel and close the previous word.

Formats
FormatWhere the MSB sits
I2S (Philips)One BCLK after the WS edge
Left justifiedAt the WS edge
Right justifiedWord ends at the next WS edge
TDMMany channels in slots on one data line

Mismatched formats give very loud or distorted audio, not silence.

Clock tree

At 48 kHz with 32-bit slots: BCLK = 3.072 MHz, MCLK at 256 × fs = 12.288 MHz. For 44.1 kHz, MCLK is 11.2896 MHz. Derive them from a PLL with low jitter, because jitter on the converter clock turns into noise.

Master, slave and drift

Whoever drives SCK and WS is the clock master. Two devices with separate crystals drift apart, so a FIFO between them slowly fills or empties. Fix it by using one clock master or by sample-rate conversion.

Play with it

  • In standard I2S the MSB appears one bit clock after WS changes. Data is sampled on the rising edge.
  • Many codecs also need MCLK, often 256 × sample rate.
  • FPGA: PLL for an accurate clock, counters for SCK and WS, shift registers, a FIFO to the processing clock.

Theory in depth

Layers and addresses

Ethernet is the physical and data link layers. The 48-bit MAC address identifies an interface on the local network; the first 24 bits identify the maker. IP, UDP and TCP ride inside the payload, and ARP maps an IP address to a MAC address.

Half duplex then, full duplex now

Early shared Ethernet used CSMA/CD: listen, transmit, detect a collision, back off a random time. The 64-byte minimum frame ensured a sender was still transmitting when a collision came back. Modern switched, full-duplex links have no collisions, but the minimum size remains.

The PHY does all of this. Speed and duplex are agreed by auto-negotiation.

CRC-32 details
  • Polynomial 0x04C11DB7 (0xEDB88320 when bit-reversed).
  • Start with all ones, process each byte LSB first, invert at the end.
  • Covers destination MAC through payload and padding, not preamble or SFD.
  • A receiver can run the CRC over data plus FCS and compare with a fixed residue.
Efficiency

Each frame also costs 8 bytes of preamble and SFD and 12 bytes of gap. With 1500 payload bytes: 1500 ÷ 1538 = 97.5%. Minimum frames occupy 84 byte times, so 1 Gbps carries up to about 1.488 million frames per second, which sets your worst-case processing budget.

MII and RGMII signals

MII uses TXD[3:0], TX_EN and TX_CLK one way, RXD[3:0], RX_DV and RX_CLK the other; the PHY provides both clocks at 100 Mbps. RGMII halves the pins with double data rate and needs the clock delayed by about 1.5 to 2 ns relative to data, added by the PHY, the board or the FPGA.

USB 2.0

USB is host-controlled: a device never speaks unless the host asks.

  • Speeds: low 1.5, full 12, high 480 Mbps.
  • D+ and D- differential. Pull-up on D+ means full speed, on D- low speed. High speed is negotiated after reset.
  • NRZI: a 0 toggles the line, a 1 holds it. After six 1s a 0 is stuffed.

Theory in depth

Topology and timing

One host, up to 127 devices in a tree through hubs. The host schedules everything in 1 ms frames (full and low speed) or 125 µs microframes (high speed), each marked by Start Of Frame at full and high speed.

Endpoints and pipes

A device exposes endpoints, numbered buffers with a direction. Direction is named from the host: IN moves data to the host. Endpoint 0 handles control and every device has it.

Packet anatomy
PartContent
SYNCEdges for the receiver to lock onto
PID4-bit type plus its complement
BodyAddress and endpoint, frame number, or data
CRCCRC5 for tokens, CRC16 for data
EOPEnd marker
One transaction
Host:   OUT token → DATA0 packet
Device: ACK | NAK | STALL

DATA0 and DATA1 alternate. If an ACK is lost, the host resends and the device sees a repeated toggle, so it discards the duplicate.

Line states

J and K are the two differential states. SE0 is both lines low: briefly it marks end of packet, and held for 10 ms or more it resets the device.

Enumeration and descriptors
  1. Host sees the pull-up and resets the port.
  2. Reads the device descriptor at address 0.
  3. Assigns an address.
  4. Reads configuration, interface and endpoint descriptors.
  5. Selects a configuration and loads a driver by class.

Common classes: HID (keyboards), CDC (virtual serial port), Mass Storage.

Power

A USB 2.0 device may draw 100 mA until configured, and up to 500 mA after the host allows it.

Play with it

  • Packets: token (IN, OUT, SETUP, SOF), data, handshake (ACK, NAK, STALL).
  • Transfers: control (setup), bulk (reliable, no timing guarantee), interrupt (bounded latency), isochronous (guaranteed timing, no retry).
  • Enumeration: reset, read descriptors, assign address, select configuration.
  • FPGA: high speed normally needs an external ULPI PHY (8 bit, 60 MHz). Many designs use a USB-UART bridge.

Theory in depth

Setup, hold and metastability

A flip-flop needs data stable for a setup time before the clock edge and a hold time after it. An asynchronous input will eventually violate this. The output may then hover and resolve late. A synchronizer gives it a full cycle to settle.

MTBF = e^(t_resolve / τ) / (T0 × f_clk × f_data)

Mean time between failures grows exponentially with settling time, which is why a second flop helps so much. It lowers the risk; it never makes it zero.

Asynchronous FIFO

Write and read pointers carry one extra bit and cross domains in Gray code.

  • Empty: read pointer equals the synchronized write pointer.
  • Full: the two Gray pointers differ in their top two bits and match in the rest.
  • Synchronized pointers are old, so the flags are pessimistic, never unsafe.
FIFO depth

A writer sends a burst of 120 words at 100 MHz, one per cycle, while the reader drains one per cycle at 50 MHz. The burst lasts 1.2 µs, in which the reader takes 60. Depth needed is at least 60, plus margin for synchronizer delay.

FSM discipline
  • One state register, a clear reset state, and a default branch.
  • Register outputs that leave the module.
  • Draw the states before writing code.
Timing constraints for I/O

The tools only analyse what you describe. Declare every clock, tell them input and output delays relative to the external device, and mark true asynchronous crossings deliberately. Use the registers inside the I/O blocks for repeatable pin timing.

Why not 2-FF each bit of a bus?

Bits can land in different cycles and form a value that never existed. Use a handshake or async FIFO.

Why Gray code in FIFO pointers?

One bit changes per step, so a sample is either the old or new value.

What is metastability?

A flip-flop with violated setup or hold takes an unpredictable time to settle.

How do you verify a protocol block?

Simulate against a model of the other side, include errors and back-to-back transfers, assert handshake rules, then check on hardware with a logic analyzer.
